# 乐颜 · 本地真实后端运行手册（Node + PostgreSQL · 苍穹双轨）

> 让「乐颜」在你本机**前后端完整跑起来**：前端 React + 真实 Node 后端 + 真实 PostgreSQL。
> 同一套前端代码，本地连 Node、上线连金蝶苍穹——只换 base 地址，这就是「双轨」。

## 一、三种数据模式（同一套 `api.ts`）

| 模式 | 取值 `VITE_DATA_BACKEND` | 数据落地 | 适用 |
|---|---|---|---|
| local | `local` 或留空(未检测到苍穹) | 浏览器 localStorage | 零后端演示，刷新不丢 |
| **server** | `server` | **本地 Node + PostgreSQL** | 本机前后端完整联调 |
| cosmic | `cosmic` 或留空(检测到苍穹) | 金蝶苍穹控制器 → PostgreSQL | 生产部署 |

> 关键：`server` 与 `cosmic` 都走苍穹 KAPI 形态 `POST /ierp/kapi/app/<控制器>/<方法>`，
> 所以本地真后端与苍穹**前端零改动**互换。

## 二、一键启动（推荐）

```bash
cd leyan
npm run dev:all
```

这条命令会自动按序：
1. 探测 `localhost:5432` 是否有 PostgreSQL；
2. 没有则尝试 `docker compose up -d db` 起一个（需装 Docker），等待就绪；
3. `npm install --prefix server` 装后端依赖（首次）；
4. `node server/migrate.mjs` 建表 + 灌脱敏种子；
5. 并发启动 **后端 API(8788) + AI 代理(8787) + 前端(3000)**；
6. 打印各地址与数据模式。

> **降级保证**：若既无 PostgreSQL 又无 Docker，启动器自动让前端以 `local` 模式启动，
> 演示照常可用，绝不白屏。补齐 PG 后再 `npm run dev:all` 即升级为真实后端。

打开 http://localhost:3000 → 学生 `/` · 教师 `/teacher` · 管理 `/admin`，
演示账号见登录页「一键填入」，密码统一 `leyan123`。

### 零依赖测试模式（pg-mem，无需 PostgreSQL / Docker）

想完整体验「真实后端 server 模式」但没装 PG/Docker，可用内存版 PostgreSQL：
```bash
# 终端1：后端用 pg-mem（进程内自动建表 + 灌种子；重启即重置）
set PG_MEM=1 && npm run backend           # Windows；macOS/Linux: PG_MEM=1 npm run backend
# 终端2：前端连 server
set VITE_DATA_BACKEND=server && npm run dev
```
打开 http://localhost:3000 即跑通真实「前端 → 后端 → SQL」全链路（数据在内存，演示足够）。
> 本项目三端 24 功能 + 全部 9 个控制器即用此模式联调验证通过；正式部署仍用真实 PostgreSQL。

## 三、手动启动（看清每一步）

```bash
cd leyan
# 1) 起库（用自带 docker-compose；或指向你已有的 PostgreSQL）
npm run db:up                 # docker compose up -d db
# 2) 配置后端连接（默认已对齐 docker 的 leyan/leyan/leyan@5432）
copy server\.env.example server\.env        # 需要改连接信息时编辑它
npm install --prefix server   # 装 pg 驱动（首次）
# 3) 建表 + 种子
npm run db:migrate            # node server/migrate.mjs
# 4) 起后端 API
npm run backend               # node server/index.mjs  → http://localhost:8788
# 5) （可选）起 AI 代理：真实大模型，见 docs/接入真实大模型.md
npm run proxy
# 6) 起前端（server 模式）
copy .env.example .env.local  # 内含 VITE_DATA_BACKEND=server
npm run dev                   # http://localhost:3000
```

## 四、用你自己的 PostgreSQL（不依赖 Docker）

编辑 `server/.env`：
```
PGHOST=你的主机   PGPORT=5432   PGUSER=xxx   PGPASSWORD=xxx   PGDATABASE=leyan
# 或整串：DATABASE_URL=postgres://user:pass@host:5432/leyan
```
然后 `npm run db:migrate` 建表灌种子，再 `npm run backend`。

## 五、健康自检

- 后端：浏览器开 `http://localhost:8788/api/health`
  - `{"ok":true,"db":true,...}` → PostgreSQL 已连通；
  - `db:false` → 库没起/连不上，前端会优雅报错并提示。
- AI 代理：`http://localhost:8787/api/health`（`hasKey:true` 才走真实模型）。

## 六、数据模型与控制器映射

12 张 `ly_*` 表见 `docs/数据库与领域模型规格.md`，建表脚本 `server/schema.sql` 与之一一对应。

| 前端 api | 苍穹控制器 `app/ks/controller` | 本地后端路由 | 实体 |
|---|---|---|---|
| MoodApi | MoodController | /MoodController/{getHistory,checkin,listStories} | ly_mood_log·ly_garden_story·ly_alert |
| DiaryApi | DiaryController | /DiaryController/{list,create} | ly_diary |
| TreeholeApi | TreeholeController | /TreeholeController/{list,create,toggleHug} | ly_treehole(_hug) |
| GalleryApi | GalleryController | /GalleryController/{list,create} | ly_artwork |
| TalkApi | TalkController | /TalkController/{list,create,toggleFollowUp} | ly_talk_record |
| AlertApi | AlertController | /AlertController/{list,advance} | ly_alert |
| ResourceApi | ResourceController | /ResourceController/{list,create,update,toggle,remove} | ly_resource |
| ConfigApi | ConfigController | /ConfigController/{get,save} | ly_config |
| AuthApi | AuthController | /AuthController/{login,me} | ly_user |

> 本地后端 `server/index.mjs` 与苍穹控制器是**镜像实现**：同方法名、同入参、同 `{code,data}` 出参。

## 七、闭环亮点：心情打卡 → 预警联动

学生连续 N 次（默认 3，可在管理端系统配置调）情绪低落（low/anxious/sad），
`MoodController.checkin` 自动写入 `ly_alert` 并（苍穹侧）触发预警工作流，
管理端「预警中心」即出现该预警，可推进 待处理→干预中→已闭环。
这打通了**学生端 → 管理端**的核心业务闭环（赛题功能闭环分）。

## 八、安全

- 登录密码只存 **sha256 摘要**（`ly_user.pwd_hash`），不存明文；后端校验摘要、签发随机会话 token。
- 数据库连接、AI Key 只在服务端（`server/.env`、`proxy/.env`，均 gitignore），浏览器/仓库永不持有。
- 全部为**脱敏模拟数据**，学生以编号关联，无真实姓名/学号。

## 九、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 健康 `db:false` | 库没起/连接错 | `npm run db:up` 或检查 `server/.env`，再 `npm run db:migrate` |
| 前端数据报错 | server 模式但后端/库没起 | 起后端+库；或临时改 `VITE_DATA_BACKEND=local` 演示 |
| `npm install --prefix server` 失败 | 离线 | 联网后重试；期间前端自动 local 模式 |
| 端口占用 | 3000/8787/8788 被占 | 关掉占用进程或改端口（server/.env 的 PORT、vite.config 的 server.port） |
